# PPE Monitor

Мониторинг средств индивидуальной защиты (каска, жилет) и запретных зон на видео.
Нейросети находят людей и СИЗ, система привязывает СИЗ к конкретным людям,
подтверждает нарушения с гистерезисом (3 с на вход, 5 с на выход) и формирует
**пакет инцидента** — данные эпизода + кадры + клип — для сервера-приёмника.

## Быстрый старт

```powershell
cd ppe_monitor
py -3.11 -m pip install -e ".[dev]"      # зависимости + pytest + приёмник
py -3.11 -m pytest                       # тесты (без GPU и видео, ~4 с)

# терминал 1 — приёмник пакетов, страница http://127.0.0.1:8000/
py -3.11 -m ppe_receiver --port 8000 --data data\receiver
# терминал 2 — мониторинг
py -3.11 main.py --source test\test_neg1.mp4
```

Полезные флаги: `--no-display`, `--no-api` (не слать по сети), `--zones zones.yaml`, `--resize 1280`,
`--device cuda`, `--max-frames 100`, `--camera-id cam_25`, `--config my.yaml`, `-v`.
Все настройки — в [config.yaml](config.yaml); флаги переопределяют его.

## Инциденты VSpark

При запуске `ppe-receiver` доступны шесть маршрутов с префиксом `/api/Metrics`.
Их схемы и форму для проверки запросов можно открыть на `http://127.0.0.1:8000/docs`.
Для установки зависимостей приёмника выполните `py -3.11 -m pip install -e ".[receiver]"` из папки `ppe_monitor`.

| Операция | Маршрут | Доступ |
|---|---|---|
| Список по убыванию даты | GET /incidents | Авторизованный |
| Метаданные | GET /incidents/{guid} | Авторизованный |
| JPEG | GET /incidents/{guid}/artifact | Авторизованный |
| Создание из multipart-полей incident и image | POST /send-incident | SA |
| Обновление camId, roomId, status, type и priority | PATCH /patch-incident | SA |
| Удаление записи вместе с JPEG | DELETE /delete-incident?guid={guid} | SA |

Задайте в окружении приёмника `PPE_METRICS_API_KEY` для доступа с ролью SA через
`X-API-Key`. Для Bearer JWT настройте `PPE_METRICS_JWT_SECRET` (общий секрет HS256
с вашим издателем, минимум 32 случайных байта), а также `PPE_METRICS_JWT_ISSUER`
и `PPE_METRICS_JWT_AUDIENCE` согласно полям токена. Приёмник проверяет подпись
и срок действия `exp`. Для записи требуется значение SA в role, roles или стандартном
URI роли .NET.

Чтобы направить оповещения монитора в этот приёмник, задайте `visdash.url` равным
`http://127.0.0.1:8000/api/Metrics/send-incident`. В окружении монитора задайте
`PPE_VISDASH_API_KEY` (значение ключа приёмника) или `PPE_VISDASH_BEARER_TOKEN`
(действующий JWT с ролью SA). Для удалённого сервера используйте HTTPS и
`visdash.ssl_verify: true`. При открытии эпизода монитор отправляет статус Pending,
тип NoPPE для СИЗ или ZoneTimeout для запретной зоны, время начала и стартовый кадр.
Инциденты Metrics хранятся в отдельной таблице SQLite вместе с JPEG. Пакеты
эпизодов и клипы доступны через существующий API `/api/v1/incidents`.

## Архитектура

```
 cli.py — сборка: читает конфиг, создаёт объекты, соединяет их
   │
   ▼
 pipeline/  ── адаптеры ввода ──────────────────────────────────────────
   source.py    FileSource / LiveSource  → Frame (кадр + время кадра)
   detector.py  YoloDetector             → Person[], PPEItem[]
   │
   ▼
 domain/  ── ЧИСТОЕ ЯДРО: без cv2 / torch / numpy / config ───────────
   association.py      СИЗ → люди (по областям тела, один объект — одному)
   compliance.py       есть / нет / не видно — по каждому СИЗ   ┐
   zones.py            в зоне / вне / не видно — по каждой зоне ├→ Observation[]
   analyzer.py         объединяет правила                       ┘
   episode_tracker.py  гистерезис → EpisodeEvent: opened / updated / closed
   │
   ▼
 pipeline/evidence.py — кадры, «лучший» кадр, клип ±5 с → IncidentPackage
   │
   ▼
 sinks/  ── адаптеры вывода (outbox на диске: переживает обрывы и рестарты) ──
   files.py     локальная копия пакетов + data/logs/incidents.jsonl
   receiver.py  пакеты → приёмник; тревоги идут раньше тяжёлых клипов
   visdash.py   старый дашборд: только факт открытия нарушения
 ui/       отрисовка и окно предпросмотра

 ppe_receiver/ — отдельное приложение: демо-приёмник пакетов (FastAPI + SQLite)
```

**Главное правило:** `domain/` ничего не знает о камерах, нейросетях, файлах и HTTP.
Время, координаты и настройки приходят параметрами. Поэтому всё ядро
проверяется быстрыми тестами (`tests/`), а адаптеры можно заменить, не трогая логику.

### Поток данных одного кадра

1. `Frame` — изображение, номер, **время кадра** (для файла — позиция в видео).
2. `Detector.detect` → люди (с `track_id` и ключевыми точками позы) и СИЗ.
3. `associate` — каждая каска ищет человека, у которого она **в области головы**,
   жилет — в области торса. Каска в руке не считается надетой.
4. `evaluate` — чего не хватает. Если часть тела не видна (спиной, обрезан кадром) —
   статус `UNKNOWN`, а не нарушение: «не вижу» ≠ «нет».
5. `zone_observations` — стоит ли человек (точка стоп) в запретной зоне.
6. `EpisodeTracker` — гистерезис (ниже) превращает наблюдения в эпизоды.
7. `EvidenceCollector` — собирает доказательства и пакеты, раздаёт получателям.

### Гистерезис: когда нарушение начинается и заканчивается

Отдельный автомат на каждую пару (человек, СИЗ) и (человек, зона):

```
NORMAL ──[СИЗ нет ≥ 3 с и доля «нет» ≥ 0.6]──► VIOLATION   → opened (тревога)
VIOLATION ──[СИЗ видно ≥ 5 с подряд]──────────► NORMAL      → closed (resolved)
VIOLATION ──[человек пропал > 30 с]───────────► удалён      → closed (track_lost)
```

- **Секунды, а не кадры**: промежуток между кадрами засчитывается тому, что было
  видно в его начале — падение FPS не меняет смысл порогов.
- **«Не видно» замораживает таймеры** (спиной, обрезан кадром): не засчитывается
  ни в нарушение, ни в «порядок».
- **Мигание детектора не плодит тревог**: снял/надел каску на 2 с — тот же эпизод.
- **ID switch**: новый трек рядом с пропавшим нарушителем наследует его эпизод.
- Каска и жилет — **отдельные эпизоды** (снял жилет после каски — новая тревога).

Параметры — `config.yaml → timing`, отдельно для `ppe` и `zone`.

### Пакет инцидента

| Статус    | Когда                        | Файлы                                                            |
| --------- | ---------------------------- | ---------------------------------------------------------------- |
| `opened`  | сразу при подтверждении      | `frame_start.jpg` (с разметкой), `raw_start.jpg` (исходный)      |
| `updated` | напоминание (`reminder_sec`) | `frame_current.jpg`                                              |
| `closed`  | нарушение кончилось          | + `frame_best.jpg`, `frame_end.jpg` (если устранено), `clip.mp4` |

`manifest` (схема `ppe-incident/1`): `episode_id`, камера, тип, `track_ids`, время
начала / подтверждения / конца, длительность, причина закрытия, бокс, уверенность,
смещения в видео, модель и список файлов с **SHA-256**. Тревога не ждёт клипа:
клип кодируется в фоне и уходит в `closed`. При `evidence.blur_faces: true`
головы на отправляемых кадрах размываются, исходный кадр остаётся только локально.

Полный референс формата, протокола отправки и требований к серверу —
[docs/incident-package.md](docs/incident-package.md), JSON Schema —
[docs/incident-package.schema.json](docs/incident-package.schema.json).

### Как добавить новое правило

Напишите в `domain/` функцию `(persons, ...) -> list[Observation]` с новым `rule`,
вызовите её в `Analyzer.analyze`, добавьте тайминги в `config.yaml → timing`
и тесты. Конвейер, получатели и отрисовка менять не нужно.

## Запретные зоны

```powershell
py -3.11 tools\draw_zones.py --source test\test2.mp4 --out zones.yaml
py -3.11 main.py --source test\test2.mp4 --zones zones.yaml
```

ЛКМ — точка, Enter — замкнуть зону (имя спросят в консоли), `s` — сохранить.
Координаты хранятся в долях кадра (0..1), поэтому от `--resize` зоны не съезжают.
Чтобы зоны были всегда, укажите `rules.zones_file: zones.yaml` в конфиге.

## Модели

| Файл                           | Назначение                                                                                       |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `yolov8n-pose.pt`                | люди + 17 ключевых точек + трекинг                                                 |
| `PPE_M_YOLO.pt`                  | СИЗ: `boots, gloves, helmet, human, vest` (обучена на 1280)                                  |
| `PPE_M_YOLO_{640,960,1280}.onnx` | то же в ONNX; `models.imgsz` должен совпадать с числом в имени          |

При старте проверяется, что PPE-модель знает все классы из `rules.required_ppe` —
иначе понятная ошибка вместо «вечных нарушений».

`imgsz: auto` выбирает 1280 на GPU ≥ 6 ГБ, 960 на слабом GPU, 640 на CPU.

## Выходные данные

- `data/incidents/<дата>/<episode_id>/` — локальная копия пакетов: файлы +
  `opened.json` / `closed.json` (манифесты, включая локальные файлы);
- `data/logs/incidents.jsonl` — журнал: строка на каждое событие эпизода;
- `data/outbox/receiver/{alerts,packages}/` — ещё не принятое приёмником
  (отправится автоматически, в т.ч. после перезапуска); `failed/` — отклонённое (4xx);
- `data/outbox/visdash/` — то же для старого дашборда;
- `data/logs/ppe_monitor.log` — лог работы.

> `data/` содержит фотографии людей — это персональные данные. Папка в `.gitignore`.

## Приёмник пакетов (демо)

```powershell
py -3.11 -m ppe_receiver --port 8000 --data data\receiver
```

| Метод и путь                              | Что делает                                       |
| ----------------------------------------- | ------------------------------------------------ |
| `POST /api/v1/incidents`                  | принять пакет: `manifest` (JSON) + `files`       |
| `GET /api/v1/incidents`                   | список эпизодов                                  |
| `GET /api/v1/incidents/{id}`              | эпизод со всеми пакетами                         |
| `GET /api/v1/incidents/{id}/files/{name}` | файл-доказательство                              |
| `GET /`                                   | страница для просмотра (обновляется каждые 10 с) |

Приёмник проверяет SHA-256 каждого файла, отклоняет необъявленные файлы,
повтор пакета (`Idempotency-Key`) не дублирует, а поздний `opened` не «откатывает»
уже закрытый эпизод. Хранение: SQLite + файлы в `--data`.

## Старый дашборд VisDash

При открытии нарушения отправляется `POST multipart/form-data`: `image` (JPEG) +
`incident` (JSON `{"CamId", "RoomId", "Type", "Priority"}`), `Idempotency-Key: <episode_id>`.
Поле `Type` берётся из `visdash.incident_types` по ключу `violation_type` → правило → `default`.
**Числовые коды нужно согласовать с разработчиком дашборда** — сейчас все `0`.
