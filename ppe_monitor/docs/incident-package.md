# Пакет инцидента `ppe-incident/1` — референс

Пакет инцидента — сообщение, которое PPE Monitor отправляет на сервер о нарушении:
**манифест** (JSON с данными эпизода) + **файлы-доказательства** (кадры, клип).

| | |
|---|---|
| Версия схемы | `ppe-incident/1` |
| Машиночитаемая схема | [incident-package.schema.json](incident-package.schema.json) (JSON Schema 2020-12) |
| Примеры | [examples/opened.json](examples/opened.json), [examples/closed.json](examples/closed.json) — реальные манифесты с `test_neg1.mp4` |
| Эталонный сервер | `src/ppe_receiver` (`py -3.11 -m ppe_receiver`) |
| Проверка соответствия | `tests/test_package_schema.py` — манифесты из кода и примеры проверяются по схеме |

---

## 1. Эпизод и его пакеты

**Эпизод** — одно нарушение одного человека по одному правилу: «нет каски у человека 3»,
«человек 5 в зоне crane». У каски и жилета одного человека — **разные** эпизоды.
Все пакеты эпизода имеют один `episode_id`.

```
         нарушение видно 3 с                    СИЗ видно 5 с подряд
  ─────────────●─────────────────────────────────────●──────────────►
               │                                     │
            opened ──── updated (необязательно) ──── closed
       срочно, без клипа    напоминание         полный пакет с клипом
```

| `status`  | Когда отправляется | Срочность | Файлы |
|-----------|--------------------|-----------|-------|
| `opened`  | Нарушение подтверждено (для СИЗ — 3 с, для зоны — 1 с; настраивается в `timing`) | срочно | `frame_start`, `raw_start` |
| `updated` | Нарушение продолжается, каждые `timing.<правило>.reminder_sec` (по умолчанию выключено) | срочно | `frame_current` |
| `closed`  | Эпизод завершён — причина в `close_reason` | обычная | `frame_start`, `raw_start`, `frame_best`, `frame_end`*, `clip`* |

\* — при условиях, см. раздел 4.

Пакет `closed` **самодостаточен**: он повторяет файлы начала, чтобы сервер мог восстановить
эпизод, даже если `opened` потерялся или был отклонён.

Причины закрытия (`close_reason`):

| Значение | Что произошло |
|----------|---------------|
| `resolved` | СИЗ надето (человек вышел из зоны) и видно непрерывно `exit_sec` (5 с) |
| `track_lost` | Человек не появлялся в кадре дольше `lost_ttl_sec` (30 с) |
| `stream_ended` | Конец видеофайла или остановка программы при открытом нарушении |

## 2. Транспорт

### Запрос

```
POST {receiver.url}                      по умолчанию http://localhost:8000/api/v1/incidents
Content-Type: multipart/form-data
Idempotency-Key: <episode_id>:<status>:<event_at>

manifest = <JSON манифеста, UTF-8>        поле формы, ровно одно
files    = <файл>                         поле формы, повторяется; имя файла = evidence[].name
```

В `files` передаются **ровно** файлы из `manifest.evidence` — не больше и не меньше.

### Ответы и реакция клиента

| Ответ сервера | Смысл | Что делает PPE Monitor |
|---------------|-------|------------------------|
| `201` | Принято | Удаляет пакет из очереди |
| `200` + `"duplicate": true` | Уже принимали (тот же `Idempotency-Key`) | Удаляет пакет из очереди |
| `429`, `5xx`, сетевая ошибка, таймаут | Временная проблема | Повторяет с паузой 1, 2, 4… до `retry_max_delay_sec` (60 с) |
| `400`, `404`, `413` и прочие `4xx` | Пакет некорректен, повтор не поможет | Переносит в `data/outbox/receiver/failed/` для разбора |

### Гарантии доставки

- **Хотя бы один раз.** Пакет удаляется из очереди только после ответа `2xx`. Возможны
  повторы — сервер обязан быть идемпотентным (раздел 6).
- **Переживает сбои.** Очередь лежит на диске (`data/outbox/receiver/`) и досылается после
  восстановления сети и после перезапуска программы.
- **Тревоги — вне очереди.** Две очереди: `alerts` (`opened`, `updated`) и `packages` (`closed`).
  Перед каждой отправкой берётся первый элемент `alerts`, и только если он пуст — `packages`.
  Новая тревога не ждёт, пока уйдут тяжёлые клипы.
- **При выходе** программа досылает очередь до `shutdown_drain_sec` (15 с), если сервер доступен.
- **Порядок не гарантирован.** `closed` может прийти раньше `opened` (например, `opened` ушёл
  в `failed/`). Сервер должен принимать пакеты в любом порядке.

## 3. Манифест

Все поля присутствуют всегда; отсутствующее значение — `null`. Сервер обязан игнорировать
неизвестные поля (они могут появиться без смены версии).

### Идентификация

| Поле | Тип | Описание |
|------|-----|----------|
| `schema` | string | Всегда `"ppe-incident/1"` |
| `episode_id` | string | 32 hex-символа, общий для всех пакетов эпизода. Допустимы `[A-Za-z0-9_.-]{1,100}` |
| `status` | string | `opened` \| `updated` \| `closed` |
| `camera_id` | string | Идентификатор камеры из конфига (`camera_id`, флаг `--camera-id`) |
| `source` | string | Путь к видеофайлу или адрес потока — **как указан в конфиге** (см. раздел 7) |

### Что нарушено

| Поле | Тип | Описание |
|------|-----|----------|
| `rule` | string | `ppe` — нет обязательного СИЗ; `zone` — человек в запретной зоне |
| `subject` | string | Для `ppe` — класс СИЗ (`helmet`, `vest`…), для `zone` — имя зоны |
| `violation_type` | string | Готовая строка для отображения: `helmet`, `vest`, `zone:crane` |
| `track_id` | integer | Номер человека у трекера на момент события |
| `track_ids` | integer[] | Все номера за эпизод. Больше одного — трекер сменил номер (ID switch), эпизод унаследован |

### Время

| Поле | Тип | Описание |
|------|-----|----------|
| `started_at` | string | Начало нарушения: первое наблюдение нарушения в окне подтверждения (точность — интервал между обрабатываемыми кадрами) |
| `event_at` | string | Момент кадра, на котором принято решение, породившее этот пакет |
| `ended_at` | string \| null | Только `closed`. `resolved` — когда СИЗ появилось (начало 5-секундного «порядка»); `track_lost` — когда человека видели последний раз; `stream_ended` — последнее наблюдение |
| `duration_sec` | number \| null | Только `closed`: `ended_at − started_at`, секунды |
| `violating_sec` | number | Сколько секунд нарушение **реально наблюдалось** (без периодов «не видно» и без пропаданий из кадра). `violating_sec ≤ duration_sec` |
| `video_offsets_ms` | object \| null | Для видеофайлов: `{started, event, ended}` — миллисекунды от начала ролика. Для потоков — `null` |

Формат времени — ISO 8601 с миллисекундами, **местное время машины с камерой, без часового
пояса**: `2026-10-19T20:05:14.776`. Для `resolved` всегда `event_at ≈ ended_at + exit_sec`.

> ⚠️ **Видеофайлы:** `*_at` отсчитываются от момента *обработки*, а не съёмки. Для привязки к
> записи используйте `video_offsets_ms`.

### Детекция и контекст

| Поле | Тип | Описание |
|------|-----|----------|
| `confidence` | number | Максимальная уверенность детекции **человека** за эпизод (0..1). Это не уверенность в отсутствии СИЗ |
| `person_box` | integer[4] | `[x1, y1, x2, y2]` — последний известный бокс человека в пикселях обработанного кадра (после `--resize`) |
| `present_classes` | string[] | СИЗ, привязанные к человеку на кадре события. Пусто, если человека на этом кадре нет (`track_lost`, `stream_ended`) |
| `position_2d_meters` | object \| null | `{x, z}` — точка стоп на плане пола в метрах. Только при заданной `calibration` и видимых ногах |
| `frame_index` | integer | Номер кадра источника на момент события (для файлов — с учётом пропущенных кадров). `-1` — неизвестен |
| `model` | object | Какими моделями найдено: `{"pose": "...", "ppe": "...", "imgsz": 640}`. Набор ключей может расширяться |

### Файлы

| Поле | Тип | Описание |
|------|-----|----------|
| `evidence` | object[] | Список приложенных файлов, см. раздел 4 |

Элемент `evidence`:

| Ключ | Тип | Описание |
|------|-----|----------|
| `name` | string | Имя файла в запросе и на диске, `[A-Za-z0-9_.-]{1,100}` |
| `kind` | string | Вид доказательства (таблица ниже) |
| `content_type` | string | `image/jpeg` или `video/mp4` |
| `size` | integer | Размер в байтах |
| `sha256` | string | SHA-256 содержимого, 64 hex-символа в нижнем регистре |

## 4. Файлы-доказательства

| `name` | `kind` | В пакетах | Когда есть | Содержимое |
|--------|--------|-----------|------------|------------|
| `frame_start.jpg` | `frame_start` | `opened`, `closed` | всегда | Кадр подтверждения нарушения **с разметкой** (рамки, подписи, зоны) |
| `raw_start.jpg` | `raw_start` | `opened`, `closed` | всегда* | Тот же кадр **без разметки**, в разрешении обработки |
| `frame_best.jpg` | `frame_best` | `closed` | если человек был виден в нарушении | Самый наглядный кадр эпизода: максимум «площадь бокса × уверенность» |
| `frame_end.jpg` | `frame_end` | `closed` | только `close_reason = resolved` | Кадр, на котором зафиксировано устранение (СИЗ видно 5 с) |
| `frame_current.jpg` | `frame_current` | `updated` | всегда | Текущий кадр с разметкой |
| `clip.mp4` | `clip` | `closed` | если `evidence.clip_enabled` и кодирование удалось | Видео вокруг подтверждения |

\* При `evidence.blur_faces: true` файл `raw_start.jpg` **не отправляется**: он остаётся только в
локальной копии и отсутствует в `evidence` отправленного манифеста.

Цвета разметки на кадрах: красный — подтверждённое нарушение, оранжевый — нарушение видно, но
ещё не подтверждено, серый — «не видно», зелёный — всё в порядке, синий — найденные СИЗ.

### Клип

| Параметр | Значение |
|----------|----------|
| Интервал | от `event_at(opened) − clip_pre_sec` до `+ clip_post_sec` (по 5 с), но не дольше эпизода. Это клип **момента подтверждения**, а не всего эпизода |
| Частота кадров | Фактическая скорость обработки (1–30 к/с), а не исходного видео |
| Разрешение | Ширина ≤ `evidence.clip_width` (960), без увеличения |
| Кодек | `evidence.clip_codec`: по умолчанию `mp4v` — **не воспроизводится в браузере**, открывайте плеером. `avc1` (H.264) играет в браузере, но требует библиотеку OpenH264 |
| Разметка | Красная рамка вокруг нарушителя (все его `track_ids`), подпись `<violation_type> \| episode <8 символов id>` |
| Лица | Размыты при `blur_faces: true` |

### Ориентировочные размеры

| Пакет | Объём |
|-------|-------|
| `opened` | ~150 КБ (два JPEG) |
| `closed` | ~1.5 МБ (JPEG + клип ~1.2 МБ при 768×432, 10 к/с, 7 с) |

## 5. Примеры

Сокращённый `opened` (полностью — [examples/opened.json](examples/opened.json)):

```json
{
  "schema": "ppe-incident/1",
  "episode_id": "0d59265c5d424a2fae484aedbc5e9e07",
  "status": "opened",
  "camera_id": "cam_entrance",
  "rule": "ppe", "subject": "helmet", "violation_type": "helmet",
  "track_id": 3, "track_ids": [3],
  "started_at": "2026-10-19T20:05:14.776",
  "event_at":   "2026-10-19T20:05:17.779",
  "ended_at": null, "duration_sec": null, "close_reason": null,
  "violating_sec": 3.0,
  "present_classes": ["vest"],
  "video_offsets_ms": {"started": 0, "event": 3003, "ended": null},
  "evidence": [
    {"name": "frame_start.jpg", "kind": "frame_start", "content_type": "image/jpeg", "size": 79959, "sha256": "7c3c65e1…"},
    {"name": "raw_start.jpg",   "kind": "raw_start",   "content_type": "image/jpeg", "size": 65060, "sha256": "626e3b53…"}
  ]
}
```

Чем отличается `closed` того же эпизода ([examples/closed.json](examples/closed.json)):

```json
{
  "status": "closed",
  "event_at": "2026-10-19T20:05:25.620",
  "ended_at": "2026-10-19T20:05:25.620",
  "duration_sec": 7.11, "violating_sec": 7.11,
  "close_reason": "stream_ended",
  "present_classes": [],
  "video_offsets_ms": {"started": 0, "event": 7107, "ended": 7107},
  "evidence": ["frame_start.jpg", "raw_start.jpg", "frame_best.jpg", "clip.mp4 (1.2 МБ)"]
}
```

Ролик закончился раньше, чем человек надел каску, поэтому `stream_ended`, нет `frame_end`
и пустой `present_classes`.

Отправка вручную (например, для отладки своего сервера). Хеши в манифесте должны совпадать с
файлами, поэтому запускайте из папки сохранённого эпизода `data/incidents/<дата>/<episode_id>/`:

```bash
curl -X POST http://localhost:8000/api/v1/incidents -H "Idempotency-Key: test-1" -F "manifest=<opened.json" -F "files=@frame_start.jpg" -F "files=@raw_start.jpg"
```

## 6. Требования к серверу-приёмнику

Любая реализация (эталонная — `src/ppe_receiver`) **обязана**:

1. **Проверять целостность.** Каждый файл из `evidence` получен, его SHA-256 совпадает;
   необъявленные файлы — отклонить. Нарушение → `400`.
2. **Быть идемпотентной.** Повтор с тем же `Idempotency-Key` → `2xx` без дублей. Если заголовка
   нет — ключ `<episode_id>:<status>:<event_at>`.
3. **Принимать пакеты в любом порядке и не откатывать статус**: `closed` не перезаписывается
   поздним `opened` (ранг: `opened` < `updated` < `closed`).
4. **Отвечать `2xx` только после надёжного сохранения** — после ответа клиент удаляет пакет.
5. **Различать ошибки:** временные (перегрузка, БД недоступна) — `429`/`5xx`, клиент повторит;
   постоянные (некорректный пакет) — `4xx`, клиент не повторит.
6. **Игнорировать неизвестные поля манифеста.**
7. **Не доверять именам:** `episode_id` и `evidence[].name` — только `[A-Za-z0-9_.-]`, без путей.
8. Ограничивать размер файла (эталон — 100 МБ, `413` при превышении).

## 7. Безопасность и персональные данные

- Кадры и клипы содержат изображения людей — это персональные данные. Передавайте по HTTPS
  (`receiver.ssl_verify: true` по умолчанию), ограничьте срок хранения на сервере.
- `evidence.blur_faces: true` размывает головы на всём, что уходит с машины; кадр без
  размытия (`raw_start.jpg`) остаётся только в локальной копии.
- ⚠️ Поле `source` передаётся как есть. **Не указывайте в адресе потока логин и пароль**
  (`rtsp://user:pass@...`) — они попадут в манифест.
- SHA-256 в манифесте защищает от повреждения при передаче, но не от подделки: подписи нет.

---

## 8. Версионирование

- Версия — в поле `schema`. Текущая: `ppe-incident/1`.
- **Без смены версии** могут добавляться новые поля манифеста и ключи в `model`.
- **Новая версия** (`ppe-incident/2`) — при удалении или переименовании полей, изменении смысла
  или типа, новых значениях `status`, `close_reason`, `kind`.
- Сервер, получивший неизвестную версию, отвечает `400` (пакет уходит в `failed/`, не теряется).

---

## 9. Локальная копия на машине с камерой

Независимо от отправки, каждый пакет сохраняется локально (`storage` в конфиге):

```
data/incidents/<YYYY-MM-DD по started_at>/<episode_id>/
    frame_start.jpg  raw_start.jpg  frame_best.jpg  frame_end.jpg  clip.mp4
    opened.json  closed.json  updated.json   ← манифесты, ВКЛЮЧАЯ локальные файлы
data/logs/incidents.jsonl                     ← строка на каждый пакет: манифест без evidence + folder + files
```

`updated.json` перезаписывается последним напоминанием.
